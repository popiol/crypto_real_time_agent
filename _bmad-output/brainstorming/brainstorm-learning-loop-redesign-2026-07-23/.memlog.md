- (insight) long_term_plan.json fails because LLM rewrites it abstractly with no mechanism to force use of prior knowledge
- (insight) conclusions.json almost always empty — hypothesis verification requires rare timing coincidence (one version fails while another still active)
- (insight) rule_evaluation.json needs p25, p75, worst result, streak metrics, weekly signal frequency+trend, avg gain by volatility bucket (BBW)
- (decision) Replace idea-first generation with data-driven relation analysis: LLM defines indicators (and generates code), indicators computed, LLM finds patterns vs target
- (decision) Accumulating train set: features (indicators from 24h ago) + target (last 24h change) appended every cycle regardless of outcome
- (decision) Replace long_term_plan+conclusions with episodic trace store: immutable append-only records, semantic search (embeddings) for top-K retrieval
- (decision) On failure: LLM first attempts fix (new version); only if unfixable does it move to new rule from fresh relation analysis
- (decision) version_comparison.json removed — no longer comparing versions, just diagnosing current rule failure
- (decision) Indicator set persisted, LLM-generated code, only modified on failure cycle; left unchanged on success (gain > 0.5%)
- (decision) 9-step pipeline cycle: update indicators → compute → relation analysis → generate/select idea → implement → evaluate+score rules → update train set → write trace → plan next cycle
